Pretext Integration Design

Two features: Interactive Hero Greeting + Glitch Page Headings

Feature 1

Interactive Hero Greeting

The randomized greeting ("What can I help with?", "Fire away.", etc.) renders on a <canvas> via Pretext. The cursor acts as a circular obstacle — text reflows around it in real time at 60fps. Subtitle also reflows. Suggestion buttons and chat input stay as DOM below.

Rendering

Canvas 2D with prepareWithSegments() + layoutNextLine(). Cursor defines a circular exclusion zone. Each line's width reduced where circle intersects.

Performance

prepare() once on load. Layout runs per mousemove frame — ~0.07ms, well under 16ms budget. requestAnimationFrame throttled.

Font

Sohne Light (300) at ~32px for greeting, ~16px for subtitle. Matches your current design. Falls back to system font stack.

Accessibility

Hidden <p> with sr-only for screen readers. Canvas gets aria-hidden="true". Mobile falls back to static DOM text.

Feature 2

Glitch Page Headings

Page headings across the site gain a mouse-reactive glitch effect. Characters near the cursor get random CSS transforms — translate, rotate, and color shifts to green or red. Effect is subtle and characters snap back smoothly when cursor leaves.

Implementation

Pure DOM. Client-side JS splits heading text into per-character <span> elements. Mousemove listener calculates distance to each character.

Glitch Effect

Within radius: translate(Xpx, Ypx) random jitter, rotate(Ndeg), random color from [#10a37f, #ff6b6b, original]. Intensity scales with proximity.

Transitions

Fast in (80ms ease), smooth out (200ms ease). No cumulative drift. Characters always return to exact original position.

Targeting

Applied to h1 elements with a data-glitch attribute. Added to about, blog, talks, projects, and book page headings. Disabled on mobile/touch.
